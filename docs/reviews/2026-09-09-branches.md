## 阻断与修正建议

### P1：窗口变化后导出区域超过已分配图像与缓冲区

位置：`4c94163:src/platform/vulkan_host.cpp:341`、`:481`。

导出开始时依据当时的 `DisplaySize` 分配图像和读回缓冲；每帧却重新按当前窗口 `DisplaySize` 计算绘制和拷贝范围。导出期间调整窗口后，两者不再一致。

独立进程开启 Vulkan 和同步验证，复现记录：分配图像 `849×540`，随后使用 `974×666`；缓冲分配 `1,833,840` 字节，拷贝需要 `2,594,736` 字节。出现 `06079 / 06080 / 07971 / 00183` 验证错误，最终 `VK_ERROR_DEVICE_LOST (-4)`，编辑器进程退出。发生设备丢失后没有重复该复现。

修正：导出会话固定自己的视图尺寸、裁剪、相机和离屏目标；窗口变化只影响前端。若允许改变导出尺寸，必须先等待 GPU 完成、重新分配全部关联资源并保持输出帧规格一致。增加“导出过程中调整窗口、最小化/恢复”的测试，不能只在导出结束后检查窗口生命周期。

### P1：编码器不可用会终止整个编辑器

位置：`4c94163:src/platform/vulkan_host.cpp:93`、`:96`、`:299`。

`beginExport/stepExport` 在主循环中直接执行。编码器启动、目录写入、GPU 或帧写入异常没有转为导出任务失败，而是传至最外层 `graphics::run`，结束编辑器。

独立进程先修改场景形成未保存状态，再在只包含系统目录的 PATH 环境中请求 MP4。日志为 `Cannot start ffmpeg`，进程退出，MCP 连接断开；前端没有机会显示可继续编辑的失败状态。

修正：导出具有成功、失败、取消三个明确结果；在任务边界释放临时资源、恢复原播放/步骤/作用域并通知界面，保留主文档。编码器应有可取消的有界等待，不能在 UI 线程中无限等待管道写入或阻塞等待退出。补充编码器缺失、写入失败和中途退出测试。

### P2：单摆径向公式缺少适用条件

位置：`748b068:assets/formulas/formulas.json:52`，`pend_radial = F_T=mg\cos\theta`。

若这里的 `F_T` 表示绳张力，运动中的通式是 `F_T - mg cosθ = m v²/L`。当前式子只在瞬时速度为零（例如转折点）成立。若本意是重力的径向分量，则应换成明确的分量符号，而不能与 `pend_lab_FT` 的张力标注混淆。

修正：补充通式并重新生成缓存，或明确把现有资产命名/标注为转折点专用。小角度近似本身是合理的教学简化，本次没有把它当作错误。

### P2：长动画被静默压缩时长

位置：`4c94163:apps/editor/editor_animation.cpp:62`，同样逻辑在 MCP 默认帧数计算中存在。

默认帧数从 `duration × fps + 1` 得到，却直接截断到 600；时间采样仍覆盖整个 duration，编码帧率也未调整。例如 100 s、12 fps 会写 600 帧，视频实际约 50 s，演示速度变为约两倍。该结论来自代码路径与帧率计算，未额外导出长视频。

修正：明确拒绝超过上限的区间，或让用户选择采样率并同步调整输出帧率；不能在默认导出中悄悄改变时间尺度。
