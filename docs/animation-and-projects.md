# 动画工作区与独立工程（v0.3）

## 布局与入口

启动 `run-editor.ps1`。上方“布局 / 动画”切换工作区：中央保持白色示意画布，右侧为对象列表和属性，底部为时间轴。拖动画布与侧栏之间、画布与底部之间的分隔条调整尺寸。图元从“添加图元…”菜单创建，圆保留快捷按钮。

“编辑历史”打开当前文档的历史列表和历史状态滑块；它与以秒为单位的动画时间轴是两个独立游标。选择组件草稿后，看到的是该草稿自己的历史。恢复旧状态仍是一条新的可撤销操作。

本轮参考 Blender 的工作区和区域组织方式，没有实现 Blender 的自由拆分/合并窗口或三维建模功能。

## 先运行动画示例

“示例 → 公式与阶跃动画”：物块的水平位置在 0～3 s 使用 `0.5*t^2`，3～6 s 使用 `4.5+2*u`。竖直位置在 3 s 从 0 突变为 1.5。橙色箭头使用 `F(t)=4*sin(2*t)`，长度映射为 `0.5*F`。

在右侧选择物块或力箭头，在底部选择 `x / y / dy` 通道查看相应曲线。点击或拖动曲线空白区域定位时间；拖动菱形调整关键帧时间和值，松手才提交一条可撤销事务。关键帧不能落在同一时刻。先选菱形，输入精确时刻/属性值并按 Enter 提交，或选择 `linear`（线性）、`step`（阶跃保持）、`smooth`（平滑过渡）。也可以在当前时刻插入关键帧。

已有公式的参数和命名物理量也可直接在面板修改。公式通道可以直接输入表达式，按 Enter 提交。“在当前时刻分段”创建两段；每段都可以修改表达式。注意 `u` 会从新段起点重新计时，分段后需要根据预期修改局部时间表达式；系统不会替你推断连续性。

“参数 / 物理量 / 分段数据”可编辑动画完整数据，例如：

```json
{
  "parameters": {"F0": 4, "omega": 2},
  "quantities": {"F": {"expression": "F0*sin(omega*t)", "unit": "N"}},
  "channels": {
    "dy": {"kind": "formula", "segments": [
      {"start": 0, "end": 6, "expression": "0.5*F"}
    ]}
  }
}
```

该数据用于总时长 6 s、具有 `dy` 属性的箭头。物理量可以引用参数与 `t`，暂不互相引用；通道可以引用所有命名物理量。`x/y` 是绝对位置，不能与同一对象的旧 `motion/binding` 同时使用。组件草稿内部仍是静态图元，动画加在主场景中的组件实例上。

## 求值约定和物理边界

- `t` 为全局时间，`u` 为当前公式分段内的时间；单位均为秒。分段必须无缝覆盖 `[0, duration]`，边界取右侧段的值，最后一个终点包含在内。
- `sin/cos/tan` 使用弧度，`sind/cosd` 使用角度。旧组件几何表达式的 `sin/cos` 保持角度语义，以兼容斜面组件。
- 支持 `+ - * / ^`、括号、`sqrt abs exp log min max pow clamp`、常量 `pi`；不执行脚本、属性访问或系统命令。
- 关键帧范围之外保持首/末值；阶跃采用右连续约定。平滑插值采用 smoothstep，暂不提供贝塞尔手柄。
- 保存时做有界采样检查；这不能证明整个连续区间无奇点。运行时发现除零、非有限数或非法尺寸，会暂停并报告对象。错误对象暂不绘制，其他对象继续显示。
- 示意动画可以跳变，但这不意味着该运动满足动力学。`F(t)` 只改变显式映射的图形属性，不会自动积分出轨迹。动画位置不自动产生速度；需要速度绑定时必须显式提供 `vx/vy` 通道。
- 表达式输入是用于计算的公式语言。LaTeX 是数学排版语言，两者不是同一个解析器；场景中的 LaTeX 图元仍使用预编译公式库，不支持任意表达式实时 LaTeX 排版。

## 独立工程

“文件 → 打开 / 另存工程…”指定 `.physproj` 路径。`Ctrl+S` 保存整个工程。JSON 导入/导出只交换当前文档，不能代替工程保存；旧 JSON 不包含撤销栈，导入不会自动恢复旧会话的撤销。

工程是单个 UTF-8 JSON 容器，包含主场景、内嵌组件定义/实例、当前组件草稿、已经关闭的组件草稿归档、动画、两个文档各自的撤销/重做栈、历史状态、完整操作审计、布局、视图和公式遮罩资源。复制该文件后，在相同版本编辑器中可独立打开，不依赖原 `history/` 文件夹。打开后暂停播放，继续撤销/重做。

历史状态仍保留最近 101 个，撤销最多 100 次；这是编辑器的保留策略。完整操作审计不再截断至最近 1000 条，能够分页查看并随工程保存。已经关闭的组件草稿归档保存在工程 `closedDrafts` 中，当前前端尚不提供它们的重新打开列表。

公式遮罩随工程保存，但当前 GPU 字体图集仍在启动时构建，因此加载时要求与本版本的内置公式库一致；不兼容时明确拒绝，避免静默换图。Windows 字体和编辑器程序属于运行环境，不嵌入工程。

工程上限 256 MB；超出时拒绝保存，不静默丢弃历史。相同历史场景在单个文档归档中去重。保存使用同目录临时文件和原子替换；重开前校验主场景、所有草稿及历史状态，校验失败不会部分覆盖当前工程。工程打开是工作区切换，不作为原场景内的一次撤销操作；有未保存内容时需先保存或明确选择放弃。

命令行：`physics_editor.exe --project <文件.physproj> --validation`。`--scene` 继续用于旧场景 JSON。

## MCP

新增 `sample_animation`（只读采样）、`get_project`、`save_project`、`load_project`。动画写入继续使用 `apply_commands`，新增元操作 `set_animation / set_keyframe / delete_keyframe`，与人类界面共享撤销和记录。

工程读写需要最近一次 `get_project.token`，同时覆盖主场景、组件和操作记录的变化；默认拒绝覆盖已存在文件或放弃未保存修改。MCP 编辑仍同步显示原生窗口，纯查询不改变画布焦点。

## 验证

核心覆盖分段边界、阶跃、非线性公式、无效表达式、作用域归档、搬移工程、继续撤销/重做、损坏工程原子拒绝和过期令牌。GUI 测试注入真实鼠标/键盘输入检查关键帧拖动及撤销，并验证 MCP 时间同步和运行时公式错误隔离。
