# ADR 0001：参数化组件与文档范围的历史

状态：已实施（v0.2）。日期：2026-09-08。

## 决策

使用“组件定义 + 组件实例”模型。组件定义是可编辑资源，包含内部图元、局部坐标和公开参数；实例在场景中保存变换、参数覆盖及定义 ID，场景嵌入对应定义的完整快照。分组只解决整体选择与变换，不能替代参数化复用。

每个编辑文档拥有自己的历史、修订号和日志。场景与组件定义可以同时存在，独立撤销/回溯；这里的“并行”是文档范围隔离，不要求多线程同时修改数据。

组件草稿不自动改变场景实例。发布为明确的主场景事务：将经过校验的定义快照安装到场景，原有场景历史可完整恢复。组件内部逐次编辑仍留在组件历史，不复制到主场景历史。实例参数编辑属于主场景历史。

历史回溯与物理时间分离。拖动历史游标只预览旧文档状态，不向操作日志写入每个游标位置。恢复旧状态是新事务；取消预览不改变场景。物理时间轴仍表示秒，编辑历史轴表示已提交事务序号，不能混用。

MCP 请求明确指明场景或组件文档，不依赖当前窗口焦点。定义资源随场景保存必要快照，避免修改磁盘上的组件文件导致旧场景和旧历史的视觉结果悄悄变化。

## 不采用

不把所有细粒度编辑塞进全局撤销栈；不让发布组件产生几十条场景编辑；不对组件参数执行任意脚本；不通过复制像素实现组件复用；不把圆弧运动强行当作固定笛卡尔加速度运动。
